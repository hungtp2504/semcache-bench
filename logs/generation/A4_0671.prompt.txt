You generate test inputs for a semantic-cache benchmark. A semantic cache returns a
stored answer when a new query is "similar enough" to a stored query. We test exactly
where that breaks. For each seed question (given with its answer), produce 24 variant
queries along 9 axes.

GLOBAL RULES
1. Write every variant in the SAME LANGUAGE as its seed.
2. Variants must read like real user queries: natural, self-contained, no meta-text.
3. P-axes (P1,P2,P3): the seed's answer MUST remain a fully correct and complete answer
   to the variant. Never alter entities, identifiers, numbers, dates, quantifiers, or polarity.
4. N-axes (N1..N6): the correct answer to the variant MUST differ from the seed's answer.
   Add "delta": at most 12 words stating what the variant asks for instead.
5. Within one axis, variants must differ substantially from each other (no trivial
   re-punctuation). No variant may duplicate the seed or any other variant.
6. Keep surface edits MINIMAL for N3, N4, N5 — a tiny edit that flips the answer is the
   entire point of these axes. Do not "helpfully" rephrase the rest of the sentence.
7. Counts per seed, exactly: P1 x4, P2 x4, P3 x4, N1 x2, N2 x2, N3 x2, N4 x4, N5 x4,
   N6 x2 = 28. N4/N5 are generated as FOUR CANDIDATES each because their
   applicability depends on the seed (only judge-validated ones enter the dataset):
   make the four candidates try DIFFERENT anchor elements (seed predicate, answer
   polarity, answer date/amount, answer condition); if the seed truly has no
   flippable element, still produce your best four — the judge filters.

AXES (taxonomy v1.0 — full definitions in config/taxonomy.yaml)
P1 lexical paraphrase — synonyms/wording only; answer unchanged.
P2 syntactic restructure — reorder/reframe (question<->request, active<->passive); answer unchanged.
P3 surface noise — typos, abbreviations, casual register, lowercase; Vietnamese: missing
   diacritics, texting shorthand (ntn, bn, v). Content words recognizable; answer unchanged.
N1 aspect change — same topic entity, different facet (deadline -> grading criteria).
N2 scope change — narrow/widen by exactly one qualifier (assignment -> its appendix;
   students -> international students).
N3 entity substitution — swap exactly ONE entity/id/version for a plausible sibling
   (Assignment 1 -> Assignment 2); everything else as close to the seed as possible.
N4 polarity flip — flip the sign of an element PRESENT IN THE SEED with ONE
   negation/antonym (include -> exclude, open -> closed, allowed -> forbidden,
   do -> avoid). HARD CHECKS, all required:
   (a) exactly one change — never combine with an entity/aspect/scope change;
   (b) the seed's answer must NO LONGER correctly answer the variant (if the flipped
       question is still answered by the same fact — e.g. seed answer says "painless"
       and you ask "is it painful?" — it is NOT compliant; pick another element);
   (c) the variant stays bounded — no open complement sets ("which tests FAIL to
       detect X" is unbounded and non-compliant).
   BAD: "What does find do?" -> "Which module does NOT do X?"  (aspect drift + unbounded)
   GOOD: "Which files should I include?" -> "Which files should I exclude?"
N5 quantifier/extreme change — flip a quantifier or extreme that EXISTS in the seed
   or is pinned by its answer: min<->max, earliest<->latest, at least<->at most,
   first<->last, all<->none-but. HARD CHECKS, all required:
   (a) NEVER introduce a quantity dimension absent from both seed and answer
       (no invented counts, sizes, frequencies, thresholds);
   (b) if the seed has no explicit quantifier, anchor to the answer's quantity-bearing
       element (a date -> earliest/latest; an amount -> minimum/maximum);
   (c) verify the flipped question's correct answer actually DIFFERS (if only one
       item exists, "the largest X" resolves to the same X — not compliant).
   BAD: seed about tool function -> "What is the maximum number of modules?"  (invented dimension)
   GOOD: "What is the latest submission date?" -> "What is the earliest submission date?"
N6 presupposition shift — presuppose a related but different fact from the same context
   (deadline -> penalty for missing it); keep high lexical overlap with the seed.
